```
Assets/                  3D + 2D assets from the asset AI
  Units/ Enemy/ Ingame/ UI/
Scene/
  Menus/                 MainMenu, Loading
    Pages/               HomePage, SoldiersPage, UpgradePage, MissionsPage, ShopPage
    Popups/              UnitDetailPopup, SettingsPopup, HowToPlayPopup
  UI/                    HUD (battle)
    Components/          SoldierCard, UpgradeRow, MissionRow, ShopItem, ShopOffer,
                         StatRow, CurrencyPill, UnitPreview3D
  Ingame/                Battle (main battle scene), GatePair, SpikeWall, WaveTrigger
    Levels/              Level01  (road, arena, gates, traps, waves, markers), LevelTutorial (beginner level)
  Units/                 Soldier (base)
    Soldiers/            Rifleman, MachineGunner, Sniper, RocketSoldier, Medic
  Enemy/                 Enemy (base)
    Types/               Grunt, Scout, Brute, Gunner, Warlord, Boss, Kamikaze, SniperEnemy, MedicEnemy
Resources/UI/            ui_theme.tres (all button / panel / label styles)
Scripts/                 Autoload (Game, AudioManager, PlayerData, MissionManager, SaveManager, AdService, PurchaseManager), Core, Effects, Ingame, Units, Enemy, UI, Monetization, Dev
Sounds/                  generated by Tools/generate_sounds.py
Tools/                   build_level_scenes / build_ui_scenes (scene generators)
Docs/                    asset prompts, this file
```

## Flow
`MainMenu` -> PLAY -> `Loading` -> `Battle` -> victory/defeat -> `MainMenu`.
Battle rewards (gold, class shards) are credited to `PlayerData` and saved to `user://save.json` by
`SaveManager` (atomic write + `.bak`, checksum, versioned). A win records the level (`highest_level`);
CONTINUE advances to the next unlocked level, PLAY AGAIN replays the same one. Tapping the level banner on the home page opens `LevelSelectPopup`: beaten levels and the current unbeaten level are selectable (`Game.select_level`), later levels are locked. Under DAILY / FREE CHEST are 4 empty `ChestSlot`s (chest drops come later). `--sim` / `--no-save` never write.
Battles use `DayCycle`: the time of day is fixed per battle. `PlayerData.day_phase` (0 morning, 1 evening, 2 night, saved) steps once after every finished battle (`Game.end_battle`, win or loss); the Settings toggle `day_cycle` OFF = always morning and the counter freezes.
Chapters 1-3 (levels 1-15) get themed scenery from `EnvTheme` (data) + `Scenery` (built by `Level._ready`, new random layout every battle: prop clusters, lone props, decals, fence/pipe runs, 2-4 landmarks per side, ground tint). Chapters 4+ keep the plain look until their env art exists: add a folder in `Assets/Ingame/Env/` and an `EnvTheme.THEMES` entry. Test: `godot --headless --path . res://Tools/test_scenery.tscn`.

## Missions, achievements, daily login
- `MissionManager` (autoload, after PlayerData and before SaveManager) owns the state; `MissionDB` holds the data (ids, titles, goals, rewards). State is saved inside the profile (`missions` key, no version bump).
- Missions move only by playing: `Game._finish_battle` calls `MissionManager.record_battle(won, kills, shards)` once per battle (win or loss). Gold spent on upgrades comes from `PlayerData.spent`.
- Daily counters reset on a new local day, weekly counters on a new week (Monday). Achievements are lifetime; `level` and `unit_level` are read live from PlayerData. Rewards are gold or gems; basic (first-tier) achievements pay gold only.
- Daily login: 7-day strip (`MissionDB.LOGIN`), one claim per day, a missed day restarts at day 1. Claim from the Missions page or the Home DAILY button.
- Add a mission: add a row to `MissionDB.DAILY / WEEKLY / ACHIEVEMENTS`. Add a stat: add it to `MissionDB.STATS` and call `MissionManager.add`-style bump from `record_battle` / a PlayerData signal.
- Tests: `godot --headless --path . res://Tools/test_missions.tscn` (also covers the sound / music settings).

## Rewarded ads and purchases
- `AdService` (autoload): `if await AdService.show_rewarded("placement"): grant`. Backend = `AdProvider` (`Scripts/Monetization/`). On Android with the Poing Studios AdMob plugin installed, `AdService` creates `AdMobProvider` (rewarded `.../2283672426` for every rewarded placement, interstitial `.../9098287392` for placement "interstitial"; Google test units in debug builds, real units in release). Otherwise debug builds use `MockAdProvider` (3 s fake ad); a release build without the plugin has no provider, so ads are unavailable there. AdMob App ID `ca-app-pub-6794417930793183~4047025284` goes in Project Settings > Admob > General > Android. Owning `remove_ads` skips the video and pays at once.
- Ad uses: **2X GOLD** button on the win / lose popup (`Game.double_gold`, once per battle), **revive** when the army is wiped (`Game.end_battle(false)` -> state `REVIVE`, tree paused, `HUD._on_revive_offered` shows REVIVE (WATCH AD) / NO THANKS; `Game.revive()` brings back the biggest army of the run (`Game.peak_soldiers`, `Game.revive_count()`, never fewer than `RewardDB.REVIVE_SOLDIERS`) with +20% damage (`RewardDB.REVIVE_DAMAGE_BUFF`) / `Game.decline_revive()`; once per run, never in `--sim`; defeat rewards are paid only after the player declines), **free wooden chest** in the Shop only (`RewardDB.roll_chest`, cooldown `RewardDB.CHEST_COOLDOWN`, saved as `timers.chest_ready_at`; the Home page has no free chest button), **speed up a locked chest** (WATCH AD -15 min), **free shards** in the Shop (player picks an owned soldier with `UnitPickerPopup`).
- `PurchaseManager` (autoload): `await PurchaseManager.buy(id, unit)` validates, shows the payment progress overlay, pays through a `BillingProvider`, then `_deliver()` grants (`PlayerData.grant`), marks one-time products (`PlayerData.purchases`), remembers the token HASH (`PlayerData.delivered_tokens`, newest 50, saved under `billing`), saves for real (`SaveManager.persist_now()`) and only then confirms to the store (`confirm_delivery`: consume for gold / gems packs, acknowledge for `remove_ads` and `starter_bundle`). If the save fails the grant is rolled back and nothing is confirmed. Backends: Android with the GodotGooglePlayBilling plugin = `GooglePlayBillingProvider` (real store, every build, started 2 s after boot, own crash-loop guard `user://billing_guard.cfg`); debug build off Android = `MockBillingProvider`; anything else = no provider ("Store not available"). Purchases found outside `buy()` (killed mid-payment, answer after the timeout, new phone, RESTORE PURCHASES button, app resume) come back through `purchase_recovered` / `ownership_restored` and end in the same `_deliver()`. `PurchaseVerifier` = client-side checks only (state, product id, package, fields); server verification is Phase B. Full setup and Play Console steps: `Docs/IAP_SETUP.md`. Products and rewards: `ProductDB`; balance numbers: `RewardDB`.
- Owned soldiers: `PlayerData.owns(type)` (all classes for now; change only that function when soldiers become unlockable).
- UI popups for these (`BlockingOverlay`, `UnitPickerPopup`, `RewardPopup`) are built in code with `ui_theme.tres`; they have no scenes.
- Tests: `godot --headless --path . res://Tools/test_monetization.tscn` (ads, chests, revive, purchase flow, billing pipeline 8x, real provider with crafted dictionaries 9x, guard 10x, shop UI 11x).

## Enemies and bosses
- Kamikaze (explodes on contact), Marksman (`SniperEnemy`, long range) and Field Medic (heals nearby enemies, never bosses) are in `EnemyDB` / `Scene/Enemy/Types/`. Waves list them as `kamikaze` / `sniper` / `medic` fields.
- Every 5th level (`LevelDB.is_boss_level`: 5, 10, 15...) ends with the Iron Colossus in the boss arena. Every other level ends with a mini boss in the mini arena (`LevelDB.boss_kind`: levels 1-4 = Crusher, Gatling, Bomber Chief, Commander, then the cycle repeats).
- Boss and mini bosses share `Scripts/Enemy/Boss.gd`; behaviour per kind (pattern sequence, fan / slam / bomb numbers, summon size, wake distance) is the `Boss.CONFIGS` table, health / rewards are in `EnemyDB`. Mini boss scenes: `Scene/Enemy/Types/Mini*.tscn`.
- Summons use `Enemy.spawn_minions` (default 8-20 fully random enemies, pool = `EnemyDB.MINION_POOL`; each mini boss config can narrow the range).
- `Level01.tscn` holds both arenas (`Arena` = boss, `MiniArena` = mini). `Level.configure()` (called by `Battle`) removes the one that is not needed and picks the matching `BossSpawn` / `ArenaStop` markers.
- **Chests** (`Scripts/data/ChestDB.gd`): every won level drops one chest (60% wood, 30% silver, 10% gold) into a free home slot (`PlayerData.chest_slots`, `ChestDB.SLOTS` = 4; full slots lose the chest). Contents are rolled at drop time and saved, so the preview is exact: wood = 1 unit, 3-5 shards; silver = 2 units, 7-10 shards each; gold = 3 units, 20-50 shards each; plus gold (small / medium / big) and a gem chance (2% / 2% / 5%). Tap a slot on Home -> `ChestPopup` (units the player does not own show `???`) -> OPEN -> `PlayerData.open_chest` unlocks new units and pays. Won chests are locked: wooden 30 min, silver 1 h, gold 2 h (`ChestDB.UNLOCK_SECONDS`, `ready_at` saved in the chest). Tapping a locked chest shows the countdown, WATCH AD (`ChestDB.AD_SKIP_SECONDS` = 15 min off, repeatable) and OPEN NOW for gems (`ChestDB.skip_gems`, 1 gem per `ChestDB.SECONDS_PER_GEM` = 360 s, 2 h = 20 gems). `PlayerData.open_chest` refuses a locked chest. The free ad chest is a wooden chest. The shop sells a gold chest for `ChestDB.SHOP_GOLD_GEMS` gems (card shows no contents, opens at once). The shop has a wooden chest card above the gold chest (WATCH a video -> wooden chest, its own 30 min cooldown `PlayerData.chest_ready_at`; Home has no free chest, `ShopPage._watch_for_wood_chest`), gem packs (SMALL = 40 gems for $0.99), no shard packs, no season pass. NO RANDOM ADS (`remove_ads`, $4.99) is a wide card; NO RANDOM ADS perk = `PlayerData.has_no_ads()` (product owned OR free trial: `PlayerData.NO_ADS_TRIAL_BATTLES` = 3 battles, counted down per finished battle by `PlayerData.use_trial_battle`, saved as `no_ads_trial_left`). While active: every battle pays 2X gold on its own (`Game.auto_doubled`, not in `--sim`) and no random ad. Otherwise a random ad (`AdService.show_interstitial`, placement "interstitial") plays after every `Game.BATTLES_PER_AD` = 2 finished battles, when the player leaves the result screen (`Game.play_due_interstitial`, called by `HUD._leave`). The perk does NOT remove rewarded ads (chest timers, shop wooden chest, free shards, revive): `AdService.show_rewarded` always needs a real ad. Test: `test_monetization` 5x*. Owned units: `PlayerData.STARTER_TYPES` + chest unlocks (`PlayerData.unlocked`, saved); locked units are not spawned by gates or the start army. Test: `godot --headless --path . res://Tools/test_chests.tscn`.
- **Random gates and obstacles**: level 1 keeps the hand-placed `Gates` / `Traps` of `Level01.tscn`. Every other level gets a fresh layout on every battle start (`Level._enter_tree` -> `LevelRandomizer.apply`), built around the `WaveTrigger` positions: 2 gate pairs before the first wave (10-14 m and 28-32 m before the trigger) and 1 gate pair 10-14 m before every other wave. Gate buffs are random: +soldiers, x soldiers (max 2 per level), +damage, +fire rate; the two sides are always different effects. Spike rows (2-4 per level, 1-2 blocks each) sit in the quiet stretch between two waves and always leave a free corridor of at least `LevelRandomizer.MIN_GAP` (6.5 m, a full army fits); every gate / row is at least `MIN_CLEAR` (14 m) from the next one. Waves and arenas are not touched. Tune the numbers at the top of `LevelRandomizer.gd`. Test: `godot --headless --path . res://Tools/test_levelgen.tscn`.

## Rounds and enemies (15 levels)
- Round 1 = levels 1-5, round 2 = 6-10, round 3 = 11-15 (`LevelDB.chapter_of`). Bosses stay on 5, 10, 15; every other level ends with a mini boss.
- `RoundDB` decides who appears. **Round 1**: the original enemies plus Mortar (levels 2-5), Blinder (3-5), Weakener (4-5) (`RoundDB.R1_NEW`). **Rounds 2 and 3**: every level uses the whole roster (`RoundDB.roster_for`: every kind in `RoundDB.R23_ROSTER` that has a model for that round: today Breacher, Shotgunner, Kamikaze, Marksman, Medic, Mortar, Blinder, Weakener) with the `_r2` / `_r3` models; wave size still comes from the `WaveTrigger` counts in the level scene, spread over the roster by weight. Boss / mini boss summons use the same roster (`RoundDB.random_minion_kind`).
- Round models: `Enemy._apply_round_model` swaps the scene's round 1 glb for `Assets/Enemy/<model>_r2.glb` / `_r3.glb` (`"model"` key in `EnemyDB.DATA`). Kinds without that key keep their model.
- New enemies: Mortar (`MortarEnemy.gd`, lobs shells onto a marked circle), Blinder / Weakener (`DebuffEnemy.gd`, soldiers' shots scatter / deal less damage for a few seconds, see `Soldier.apply_blind` / `apply_weaken`), Shotgunner and Breacher (`PelletEnemy.gd`, 5-pellet fan / one heavy slug).
- Bosses per round (`LevelDB.boss_kind`): R1 Crusher, Gatling, Bomber Chief, Commander + Iron Colossus (level 5); R2 Icebreaker, Blizzard Gunner, Sled Rider, Frost Commander + Yeti King (10); R3 Forge Smasher, Flamecaster, Lava Mortar, Foundry Overseer + Magma Drake (15). Scenes `Scene/Enemy/Types/Mini*.tscn`, `BossYeti.tscn`, `BossDrake.tscn`; models in `Assets/Enemy/Bosses/`. Their patterns are in `Boss.CONFIGS` (a kind only lists the keys it changes, `Boss.DEFAULTS` fills the rest); HP and rewards are in `EnemyDB`. Arenas are still the round 1 ones.
- Round 2 / 3 art for grunt, scout, brute, gunner, warlord is in `Assets/Enemy/` (`<name>_r2.glb` / `_r3.glb`), so all 13 normal enemy kinds fill the round 2 / 3 waves. A kind without a model for a round is skipped for that round (`RoundDB.roster_for`). Prompts used for the art: `Docs/ASSET_PROMPTS_4_R2_R3_ENEMIES.md`. Chest opening art / sound prompts (wooden, silver, gold): `Docs/ASSET_PROMPTS_5_CHEST_OPENING.md`.

## Upgrades: two separate systems
- **Upgrades tab (army-wide)**: `GlobalUpgradeDB` + `PlayerData.try_buy_upgrade`. Gold only. Battle Income (end-of-level gold), Army Damage, Army Health, Fire Rate, Shard Luck, Reinforcements (extra start soldiers). Applied to every soldier in `Soldier.setup`, to gold in `Game.final_gold`, to shard drops in `Enemy._grant_rewards`, to the start army in `Battle`. Saved under `upgrades` in the save file. **No level limit** (only Reinforcements is capped by army size): each row shows a `TierBar` that fills inside the current tier of 10 levels and changes color every tier (`GlobalUpgradeDB.tier_color`); costs keep rising after level 10 (`LATE_GROWTH`).
- **Soldiers tab (one unit)**: `SoldierDB` + `PlayerData.try_upgrade(type)`. Gold + that class's shards. Only the selected soldier class levels up.
- Tests: `godot --headless --path . res://Tools/test_save.tscn`, `res://Tools/test_enemies.tscn`, `res://Tools/test_upgrades.tscn`, `res://Tools/test_level_select.tscn`, `res://Tools/test_rounds.tscn`, `res://Tools/test_revive_ui.tscn` (defeat / revive flow in a real battle), `res://Tools/test_upgrade_ui.tscn` (upgrade rows, tier bar, unit preview camera) and `res://Tools/test_monetization.tscn`.

## Tutorial (beginner level, guide, HOW TO PLAY, home coach marks)
- **Flow**: a fresh profile (`PlayerData.should_start_tutorial()` = `not tutorial_done and highest_level == 0`) gets the tutorial when it presses PLAY (`Game.goto_battle`). `Game.start_tutorial(replay)` is Settings > REPLAY TUTORIAL. `Game.tutorial` stays true until `Game.goto_menu` (not reset by `reset_run`, because `Battle` calls it again after the scene change); RESTART in the pause menu repeats the tutorial. `Game.level_index` is 1 during the tutorial and restored by `goto_menu`.
- **Level**: `Battle._enter_tree` swaps `Level01` for `Scene/Ingame/Levels/LevelTutorial.tscn` (about 260 m, hand-written, same node layout as `Level01`): gate 1 at z -40 (+6 soldiers | +25% damage), gate 2 at -78 (-6 soldiers | x2), wave 1 at -105 (6 basic), one 3.5 m spike wall at -150 (x +3.5, 10 damage), wave 2 at -175 (6 basic + 3 fast), mini arena entrance at -220 (level 1 mini boss, Crusher). `Battle._soften_boss` gives the boss 30% health and slow, gentle attacks (`TutorialDB.BOSS_*`). No shop, no ads, no chest drop, no mission / achievement stats, no gold or shards credited; `Game._finish_tutorial` replaces `_finish_battle`.
- **Can not be lost**: `Game.rescue_tutorial_army` refills the army to `TutorialDB.MIN_ARMY` (6); `end_battle(false)` calls it instead of ending the battle.
- **Reward**: first completion only (`PlayerData.finish_tutorial(true)`): `TutorialDB.REWARD_GOLD` (150) + one already-unlocked wooden chest. Replays and SKIP pay nothing. `PlayerData.tutorial_done` is saved as a top-level boolean (old saves load as false; no schema bump).
- **Files**: `Scripts/data/TutorialDB.gd` (every number, text, the step table, coach marks, HOW TO PLAY slides, art paths), `TutorialDirector.gd` (step state machine; one trigger and one done-condition per step id), `TutorialGuide.gd` + `Scene/Units/TutorialGuide.tscn` (Sgt. Tatter), `TutorialArrow.gd` (3D arrows), `Scripts/UI/TutorialOverlay.gd` + `Scene/UI/TutorialOverlay.tscn` (card, ring, hand, SKIP), `TutorialCoach.gd` + `Scene/UI/TutorialCoach.tscn` (home coach marks, shown once after the first tutorial or from HOW TO PLAY > MENU TOUR), `Scripts/UI/Popups/HowToPlayPopup.gd` + `Scene/Menus/Popups/HowToPlayPopup.tscn`, `TutorialIcon.gd` (draws the png or a placeholder).
- **Art**: every file is optional. `TutorialIcon`, `TutorialGuide` and `TutorialArrow` draw primitive placeholders until the file exists, so dropping the png / glb into the folder is all that is needed: `Assets/UI/Tutorial/` (guide_portrait_talk / warn / cheer, hand_drag, hand_tap, highlight_ring, arrow_pointer, bubble_9slice, howto_1_drag ... howto_6_upgrade), `Assets/Units/tutorial_guide.glb`, `Assets/Ingame/tutorial_flag.glb`. See `Docs/ASSET_PROMPTS_7_TUTORIAL.md`.
- Test: `godot --headless --path . res://Tools/test_tutorial.tscn`.

## Editing in the Godot editor
- **Level**: open `Scene/Ingame/Levels/Level01.tscn`. Move gates / traps / waves / road tiles
  like normal nodes. Gate buffs, trap width and wave counts are inspector fields.
  New wave = instance `Scene/Ingame/WaveTrigger.tscn` under `Waves` (its z is the trigger).
- **Units**: open e.g. `Scene/Units/Soldiers/Rifleman.tscn`. The model is a child you can swap.
  Stats live in `Scripts/Units/SoldierDB.gd`, enemies in `Scripts/Enemy/EnemyDB.gd`.
- **UI**: all styles come from `Resources/UI/ui_theme.tres`; buttons use the theme variations
  ButtonPrimary / ButtonSecondary / ButtonGold / ButtonDanger / ButtonDisabled / ButtonRound / TabButton,
  panels PanelPopup / PanelCard / PanelDark / PanelCurrency.
